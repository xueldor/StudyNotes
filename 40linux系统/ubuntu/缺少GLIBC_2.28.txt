缺少GLIBC_2.28的问题，说明您本地的libc6版本太低 sudo apt updatesudo apt upgrade libc6如果依然报这个问题。strings /lib/x86_64-linux-gnu/libc.so.6 | grep GLIBC_ 看到本地的最高版本是GLIBC_2.27，并且sudo apt upgrade libc6时提示最新版本就是2.27。从官网下载http://ftp.gnu.org/gnu/glibc/glibc-2.28.tar.gzcd glibc-2.28/mkdir buildcd build/../configure --prefix=/opt/glibc-2.28make -j8sudo make install这会安装到/opt/glibc-2.28。1、如果过程中提示缺gcc gawk bison,安装即可2、如果报错：glibc-2.28/build/elf/ldconfig: Warning: ignoring configuration file that cannot be opened: /opt/glibc-2.28/etc/ld.so.conf: No such file or directorysudo cp /etc/ld.so.conf /opt/glibc-2.28/etc/ 即可。注意：用编译的高版本替换原来的2.27版本，是不可能的，直接替换/lib/x86_64-linux-gnu/下的文件，会导致系统挂掉。添加环境变量也不行。原因是，glibc相当底层，系统的诸多程序和命令都依赖它。升级了glibc就有一起升级整个系统。直接替换系统原来的，会导致ls、echo、rm的基本命令都不能使用，实际系统起不来了。如果已经挂掉，1、试一下用busybox执行命令恢复。2、试一下下面的LD_LIBRARY_PATH、LD_PRELOAD方法自编译glibc的正确用法是：1、一定要指定安装路径，即上面的../configure --prefix=/opt/glibc-2.28 2、用来给个别依赖高版本glibc的程序执行，方法是：terminal中临时修改环境变量 export LD_LIBRARY_PATH=/opt/glibc-2.28/lib:$LD_LIBRARY_PATH 或者$ LD_PRELOAD=/opt/glibc-2.28/lib/libc.so.6 yourExe,注意中间空格,这样你的程序使用 GLIBC_2.28，不影响系统。注意事项：千万不要覆盖系统默认的 glibc（如 /lib, /lib64 中的 libc.so），这会导致系统无法启动，无法恢复，只能重装系统。风险极高。 最后，如果可以，最好的方案是，直接升级系统到ubuntu20. 如何升级见另外一个笔记。
