（ext4/xfs）的元数据处理开销远高于 NTFS

rm -rf dir → 递归遍历 dir 下所有文件/子目录 → 对每个文件：
  1. 减少 inode 的链接数（link count）；
  2. 标记 inode 为“未使用”；
  3. 释放文件占用的磁盘块到空闲链表；
  4. 删除该文件在目录中的目录项（dentry）；
→ 所有子项处理完后，删除 dir 自身的目录项。

方法 1：用 rsync 替换 rm -rf
# 1. 创建空目录
mkdir -p /tmp/empty_dir
# 2. 用空目录替换目标目录（--delete 会删除目标目录所有差异文件）
rsync -a --delete /tmp/empty_dir/ /path/to/your/big_dir/
# 3. 删除空目录（此时 big_dir 已空，删除极快）
rm -rf /path/to/your/big_dir /tmp/empty_dir

方法 2：挂载时优化文件系统
/dev/sda1 /data ext4 defaults,noatime,delalloc,lazy_itable_init 0 0
# 参数说明：
# noatime：不更新文件访问时间（减少 inode 修改）；
# delalloc：延迟分配数据块（批量释放）；
# lazy_itable_init：延迟初始化 inode 表（减少删除时的链表操作）。
------------noatime常用。delalloc、lazy_itable_init没用过，或许有风险。

# 格式化时启用小文件内联存储（ext4 已支持）
mkfs.ext4 -O inline_data /dev/sda1
# 挂载后，<4KB 的小文件会直接存在 inode 中，删除时无数据块释放开销

# 格式化时启用惰性 inode 初始化/清理
mkfs.ext4 -E lazy_itable_init=1,lazy_journal_init=1 /dev/sda1
# 删除文件时，仅标记 inode 为“未使用”，后台线程批量清理链表

# 挂载时将日志模式改为“只记录元数据+批量提交”
mount -o journal_mode=ordered,commit=30 /dev/sda1 /data
# commit=30：每 30 秒批量提交日志，减少刷盘次数
