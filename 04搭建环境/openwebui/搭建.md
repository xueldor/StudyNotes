官网指定python3.11,而ubuntu默认可能不是这个版本，因此：

（补充：建议以后用uv管理python版本，而不是下面的方法）

```
# 该docker只用于openwebui,如果存在版本不对的python,先卸载
apt purge python3 python3-pip python-is-python3
apt autoremove

# 安装python3.11
add-apt-repository ppa:deadsnakes/ppa -y
apt install python3.11 python3.11-venv python3.11-dev -y
python3.11 --version
update-alternatives --install /usr/bin/python3 python3 /usr/bin/python3.11 100
update-alternatives --install /usr/bin/python python /usr/bin/python3 100

# 安装pip
python3.11 -m ensurepip --upgrade
```

在venv内安装openwebui

```
mkdir -p ~/openwebui
cd ~/openwebui

# 用 Python 3.11 创建虚拟环境
python3.11 -m venv venv

# 激活虚拟环境
source venv/bin/activate

# 在虚拟环境中安装依赖
pip install open-webui # 国内网络环境可能失败，用下面
pip install open-webui -i https://pypi.tuna.tsinghua.edu.cn/simple --trusted-host pypi.tuna.tsinghua.edu.cn

apt install ffmpeg  # Open WebUI 内置了音频处理功能如语音输入、音频转文字需要 ffmpeg 工具。不使用音频相关功能则不需要装

# 退出虚拟环境
deactivate

```

启动

```
cd ~/openwebui
source venv/bin/activate
open-webui serve --port 3000
```

首次启动会联网拉取一些文件，国内可能有网络问题。因此启动前设置一下代理：

```
xue@YZ0500120190029:/workspace/data$ cat set-proxy.sh
#!/bin/bash

# 代理服务器配置
PROXY_HOST="172.17.192.1" // 安装了clash的PC IP, clash设置里打开“局域网连接”
PROXY_PORT="7897"

# 设置代理环境变量
export http_proxy="http://${PROXY_HOST}:${PROXY_PORT}"
export https_proxy="http://${PROXY_HOST}:${PROXY_PORT}"
export all_proxy="socks5://${PROXY_HOST}:${PROXY_PORT}"
export ftp_proxy="http://${PROXY_HOST}:${PROXY_PORT}"
export socks_proxy="socks5://${PROXY_HOST}:${PROXY_PORT}"

# 同时设置大写版本（部分应用使用大写）
export HTTP_PROXY="http://${PROXY_HOST}:${PROXY_PORT}"
export HTTPS_PROXY="http://${PROXY_HOST}:${PROXY_PORT}"
export ALL_PROXY="socks5://${PROXY_HOST}:${PROXY_PORT}"
export FTP_PROXY="http://${PROXY_HOST}:${PROXY_PORT}"
export SOCKS_PROXY="socks5://${PROXY_HOST}:${PROXY_PORT}"

echo " 代理已设置："
echo "   http_proxy  = $http_proxy"
echo "   https_proxy = $https_proxy"
echo "   all_proxy   = $all_proxy"

echo " 验证方法：curl -I https://www.google.com"
```



docker:

```
docker run -itd --name openwebui --hostname=ai --network host -v ~/open-webui-data:/app/backend/data openwebui_image:V1.0 /bin/bash

docker run -itd --name openwebui --hostname=ai --add-host=host.docker.internal:host-gateway -p 3000:3000 -v ~/open-webui-data:/app/backend/data openwebui_image:V2 /bin/bash
```

`--network host`是为了能从外面访问网页。docker里面也能访问宿主的端口。

`-add-host=host.docker.internal:host-gateway`会添加/etc/hosts，以便通过host.docker.internal访问宿主端口。已经有`--network host`就不需要了。而且其实也可以通过IP访问宿主。

## 问题

* 启动慢问题

```
# 解决不挂VPN, 启动openwebui特别慢的问题
export OFFLINE_MODE=true  #禁用版本更新检查等联网行为
export HF_HUB_OFFLINE=1   # 告诉Hugging Face Hub（模型库）工作在离线模式，防止它尝试自动下载模型
建议首次启动不要设，让它都拉下来。
```

* 偶发无法连接deepseek

  这不是openwebui的锅。偶发宿主机能访问`curl -v https://api.deepseek.com/v1`，docker里不能。https://www.baidu.com 也有这个问题。但是 curl  -v https://www.qq.com 永远可以。

  目前无法确认，只是推测：宿主机 OpenSSL 1.1.1f 是传统 TLS1.3 握手格式，网关识别正常；容器是新版 OpenSSL 3.x，默认发送完整的 TLS1.3 扩展集（支持更多加密 / 握手扩展）；百度、DeepSeek 部分机房的负载均衡 / CDN 网关对新版 TLS1.3 Client Hello 解析异常。qq.com 服务器做了全兼容适配，无论新旧 OpenSSL TLS1.3 握手都能正常协商降级 TLS1.2，所以容器访问 QQ 没问题。

  之所以概率性，大概是DNS 轮询解析到不同后端节点。

  * A 类机房节点：负载均衡 / CDN 网关老旧，不兼容 OpenSSL3.x 新版 TLS1.3 Client Hello，收到直接断 TCP → 报错失败
  * B 类机房节点：网关做了 OpenSSL3.x 兼容适配，能正常解析握手包 → 连接成功

  有时在容器内和宿主多执行几次这些命令就能突然恢复：

````
curl -v --tls-max 1.2 https://api.deepseek.com  # 强制TLS1.2,可以通过
curl -v --tls-max 1.2 https://www.baidu.com

curl --tlsv1.2 -v https://api.deepseek.com

nslookup api.deepseek.com
````

由此可知是因为我在ubuntu26的docker里布署openwebui,OpenSSL版本太新导致。给OpenSSL降级好像不太安全。如果能强制使用TLS1.2,就可以解决。
