cgroup 冻结器对批处理作业管理系统非常有用。这些系统根据系统管理员的需求，启动和停止一组任务，以便调度机器的资源。这种类型的程序通常在高性能计算（HPC）集群上使用，用于调度对整个集群的访问。cgroup 冻结器使用 cgroups 来描述由批处理作业管理系统启动/停止的任务集合。它还提供了一种启动和停止组成作业的任务的方法。

cgroup 冻结器对于检查点（checkpointing）运行中的任务组也很有用。冻结器允许检查点代码获取任务的一致性镜像，方法是尝试将 cgroup 中的任务强制进入静止状态。一旦任务进入静止状态，另一个任务就可以遍历 /proc 或调用内核接口来收集有关静止任务的信息。如果发生可恢复的错误，被检查点的任务可以在之后重新启动。这也允许将检查点任务在集群的节点之间迁移，方法是将收集到的信息复制到另一个节点，并在那里重新启动任务。

在用户空间中，使用 SIGSTOP 和 SIGCONT 信号序列并不总是足以停止和恢复任务。这两种信号都可以被我们想要冻结的任务观察到。虽然 SIGSTOP 不能被捕获、阻塞或忽略，但它可以被正在等待或使用 ptrace 的父任务看到。SIGCONT 尤其不适合，因为它可以被任务捕获。任何设计用来监视 SIGSTOP 和 SIGCONT 的程序可能会因为尝试使用 SIGSTOP 和 SIGCONT 来停止和恢复任务而被破坏。我们可以使用嵌套的 bash shell 来演示这个问题：

```shell
	$ echo $$
	16644
	$ bash
	$ echo $$
	16690

	From a second, unrelated bash shell:
	$ kill -SIGSTOP 16690
	$ kill -SIGCONT 16690

	<at this point 16690 exits and causes 16644 to exit too>
```

这种情况发生是因为 bash 可以观察到这两种信号，并选择如何响应它们。

另一个捕获和响应这些信号的程序示例是 gdb。事实上，任何设计用于使用 ptrace 的程序都可能会在使用这种方法停止和恢复任务时遇到问题。

相比之下，cgroup 冻结器使用内核冻结器代码来防止冻结/解冻循环对被冻结的任务可见。这允许上面的 bash 示例和 gdb 按预期运行。

cgroup 冻结器是分层的。冻结一个 cgroup 会冻结属于该 cgroup 的所有任务以及其所有后代 cgroup。每个 cgroup 都有自己的状态（自身状态）和从父级继承的状态（父级状态）。当且仅当这两种状态都是 THAWED 时，该 cgroup 才是 THAWED 状态。

cgroup 冻结器创建了以下 cgroupfs 文件：

* freezer.state: Read-write.

  当读取时，返回 cgroup 的有效状态 - "THAWED"（已解冻）、"FREEZING"（正在冻结）或 "FROZEN"（已冻结）。这是自身状态和父级状态的组合结果。如果任何一个状态是正在冻结，则该 cgroup 就是正在冻结状态（FREEZING 或 FROZEN）。

  当属于该 cgroup 及其后代的所有任务都变为冻结状态时，处于 FREEZING（正在冻结）状态的 cgroup 会转变为 FROZEN（已冻结）状态。需要注意的是，如果有新任务被添加到该 cgroup 或其后代 cgroup 中，cgroup 会从 FROZEN 状态回到 FREEZING 状态，直到新任务被冻结。

  当写入时，设置 cgroup 的自身状态。允许两个值 - "FROZEN"（已冻结）和 "THAWED"（已解冻）。如果写入 FROZEN，该 cgroup（如果尚未处于冻结中状态）将进入 FREEZING（正在冻结）状态，同时其所有后代 cgroup 也会进入该状态。

  如果写入 THAWED，该 cgroup 的自身状态将变更为 THAWED（已解冻）。请注意，如果父级状态仍处于冻结中，则有效状态可能不会变为 THAWED。如果一个 cgroup 的有效状态变为 THAWED，那么所有因该 cgroup 而处于冻结状态的后代 cgroup 也将离开冻结状态。

* freezer.self_freezing: Read only.

  显示自身状态。如果自身状态是 THAWED（已解冻），则为 0；否则为 1。当且仅当最后一次写入 freezer.state 的是 "FROZEN"（冻结）时，这个值才是 1。

* freezer.parent_freezing: Read only.

  显示父级状态。如果该 cgroup 的所有祖先都没有被冻结，则为 0；否则为 1。

根 cgroup 是不可冻结的，上述接口文件不存在。

* 使用示例 :

  ```
     # mkdir /sys/fs/cgroup/freezer
     # mount -t cgroup -ofreezer freezer /sys/fs/cgroup/freezer
     # mkdir /sys/fs/cgroup/freezer/0
     # echo $some_pid > /sys/fs/cgroup/freezer/0/tasks
  ```

获取freezer 子系统的状态：

```shell
   # cat /sys/fs/cgroup/freezer/0/freezer.state
   THAWED
```

冻结容器内的所有task：

```shell
   # echo FROZEN > /sys/fs/cgroup/freezer/0/freezer.state
   # cat /sys/fs/cgroup/freezer/0/freezer.state
   FREEZING
   # cat /sys/fs/cgroup/freezer/0/freezer.state
   FROZEN
```

解冻容器内的所有task：

```shell
   # echo THAWED > /sys/fs/cgroup/freezer/0/freezer.state
   # cat /sys/fs/cgroup/freezer/0/freezer.state
   THAWED
```

这是一个基本机制，它应该能在简单场景下为用户空间任务做正确的事情。
